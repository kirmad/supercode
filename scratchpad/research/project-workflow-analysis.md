# Project Workflow Package Architecture Analysis

## 📋 Package Structure Overview

The project-workflow package follows a well-structured, interface-driven architecture with clear separation of concerns:

```
packages/project-workflow/
├── src/
│   ├── core/                    # Core abstractions and utilities
│   │   ├── interfaces.ts        # Main interface definitions
│   │   ├── workflow-factory.ts  # Factory for creating workflows
│   │   ├── workspace-manager.ts # File system operations
│   │   └── utils.ts            # Utility functions and error classes
│   ├── review/                  # Review workflow implementation
│   │   ├── review-workflow-processor.ts
│   │   ├── session-processing-engine.ts
│   │   ├── file-boundary-sharding-strategy.ts
│   │   └── review-result-aggregator.ts
│   ├── sources/                 # Content source implementations
│   │   └── ado-content-source.ts
│   ├── types/                   # Type definitions and enums
│   │   └── index.ts            # Comprehensive type system
│   └── index.ts                # Public API exports
├── test/                       # Test files and examples
└── docs/                       # Architecture documentation
```

## 🏗️ Core Architecture Patterns

### 1. Interface-Driven Design
The system is built around well-defined interfaces in `/src/core/interfaces.ts`:

- **`IWorkflowProcessor<TInput, TResult>`** - Main orchestrator for workflows
- **`IContentSource`** - Abstraction for content retrieval
- **`IShardingStrategy`** - Content splitting strategies
- **`IProcessingEngine`** - Parallel processing with session management
- **`IResultAggregator<TResult>`** - Result transformation and aggregation
- **`IWorkspaceManager`** - File system and workspace management

### 2. Factory Pattern
`WorkflowFactory` provides centralized workflow creation with:
- Environment-based configuration via `createFromEnvironment()`
- Dependency injection and component initialization
- Default configuration management
- Support for batch workflow creation

### 3. Session Management Architecture
`SessionProcessingEngine` handles:
- **Session Lifecycle**: Create → Process → Cleanup
- **Parallel Processing**: Batch-based execution with controlled concurrency
- **Error Handling**: Retry logic with exponential backoff
- **Resource Management**: Active session tracking and cleanup

## 🔑 Key Findings for Operation Subscription Integration

### 1. Workflow ID Generation
- Uses `generateId()` utility from `core/utils.ts`
- Pattern: `{prefix}-{timestamp}-{random}` (e.g., `workflow-1702934567abc-def123`)
- Stable hashing available via `createHash()` function
- Session IDs are UUIDs generated by the OpenCode server

### 2. Session Management Patterns
- **Session Creation**: POST to `/session` with provider/model config
- **Message Processing**: POST to `/session/{sessionId}/message`
- **Session Cleanup**: DELETE `/session/{sessionId}`
- **Active Session Tracking**: `Set<string>` for session IDs

### 3. Event Handling Patterns
Current system has:
- **Processing Status Enum**: `IDLE`, `PROCESSING`, `COMPLETED`, `CANCELLED`, `ERROR`
- **Partial Results Tracking**: `getPartialResults()` method
- **Cancellation Support**: `cancel()` method with cleanup
- **Statistics Collection**: Processing time, success rates, etc.

### 4. Error Handling and Logging
- Custom error classes: `WorkflowError`, `ValidationError`, `ProcessingError`
- Structured logging with `createLogger()` utility
- Graceful degradation with partial results
- Retry logic with configurable attempts and backoff

### 5. Type System Architecture
Comprehensive type system in `/src/types/index.ts`:
- **Base Types**: `WorkflowInput`, `WorkflowResult`, `WorkflowMetadata`
- **Enums**: Well-defined for `SourceType`, `ProcessingStatus`, etc.
- **Configuration Types**: Nested config objects with defaults
- **Result Types**: Review-specific insights, hunks, comments
